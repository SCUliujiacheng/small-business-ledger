# 从记一笔到每天用

这次补的是日常记账中容易丢信息的三个环节：谁还没付、重试有没有记重、改错前能不能找回原账。继续使用本机单用户架构，金额和利润口径不变。

## 往来与到期日

每条销售可填 `customer`、`supplier`、`receivable_due_date`、`payable_due_date`。销售的客户欠款和直接成本付款是两件事，分别计算；一笔销售只支持一个客户和一个成本收款方。费用只使用供应商/收款方和付款到期日。名称最长 120 字，可留空；到期日可留空，但不能早于业务日。

欠款清单按截止日计算，只使用截止日前的有效业务和有效流水。销售拆成销售收款、直接成本付款两个方向，费用形成费用付款方向。到期日早于截止日才算逾期，当天到期单列，没有到期日显示“未设到期日”。清单合计必须与同截止日概览的未收、未付一致。历史截止日的欠款可能已经在后来结清，登记时以当前全时间余额校验。

## 重复提交

录入业务和收付款可带 `Idempotency-Key`（标准 UUID）。请求编号、规范化请求摘要、记录编号与业务写入处于同一 SQLite 事务。同一编号同一内容重试返回同一条记录的当前状态；同一编号改内容返回 409。作废后重试不会重新创建有效记录。网页的一次提交在失败重试时沿用编号，不将相同金额的两笔真实业务误合并。该保护不替代用户核对：关闭页面重新录入属于新的操作。

## 备份与升级

数据库版本升级为 2：增加上述字段和请求去重索引。旧数据以空名称、空到期日迁移；未知的更高版本拒绝打开，不尝试降级。升级已有非空账本前先生成可校验的旧格式备份，迁移在事务中完成，可重复启动。

每次改变非空账本前，在数据库旁的 `<数据库文件名>.backups` 文件夹保存一致的 JSON 快照。写入临时文件、校验、刷盘、原子发布成功后才允许修改；失败则账目不变。仅轮换此目录内工具生成的自动备份，保留最近 30 份，不清理其他文件。空账本第一次写入无需备份。界面显示备份目录、时间和大小，可下载或手动生成当前快照；不提供覆盖当前账本的恢复操作。自动备份通常比当前账本少最后一笔变化，搬家或关机前可另下载当前完整备份。

同一块硬盘上的备份不能防硬盘损坏，文件也未加密。重要账目仍需另外保存一份。快照使用数据库事务内的一致读取，不直接复制正在使用的 SQLite 主文件；WAL 模式下主文件不一定包含所有已提交数据，参见 [SQLite 备份说明](https://www.sqlite.org/backup.html)。

超额付款、重复编号、批量导入超出容量等可预先判定的失败，会在同一写事务里先行拒绝，不生成快照、不挤掉恢复点。备份目录不接受符号链接或 Windows 目录联接；文件名、日期和完整内容校验通过的文件才参与轮换。未知格式或损坏文件留在原处，不自动清理。恢复版本 2 备份时，还会从每条记录重建录入内容，与去重索引的摘要核对，防止请求编号被错误关联到别的单据。

JSON 导出版本 2，包含往来字段和去重索引；继续接受版本 1 的完整备份。旧版 CSV 仍可导入，新模板增加四个可选字段，导出时保持公式转义。恢复仍然只允许空账本，保留记录 ID、付款关联、作废历史与示例标记。

## 不在本轮范围内

退款、预收预付、库存、期初应收应付迁入、税务和多人权限仍未实现。不把这些业务用作废或改日期来替代。10,000 条容量仍包含作废记录，导出不会释放容量。这一版用于范围适合的小店和工作室试用，不宣称替代正式会计系统。
